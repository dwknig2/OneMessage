# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

OneMessage is a single Python 3.11+ generator script, `setup_unified_timeline.py`. It does not itself process any messages — running it *writes out* a separate `unified_jess_timeline/` project (config file, `requirements.txt`, `.gitignore`, staged pipeline scripts, a bash wrapper, a `launchd` plist, and a README). That generated project is the actual "Unified Jess Timeline" data pipeline: it ingests Apple Messages, transcribes audio with `faster-whisper`, and merges multiple sources (Messages, Google Voice, Google Chat, Alexa) into a unified JSON/Markdown timeline.

`unified_jess_timeline/` itself is git-ignored (see `.gitignore`) — it's build output, not something to commit.

## Environment setup

- `.cursor/install.sh` (wired via `.cursor/environment.json`) bootstraps the dev environment: installs the `python3-venv` system package if `ensurepip` is missing, creates a project-local virtualenv at `.venv`, and installs `requirements.txt`. It is idempotent — safe to re-run.
- Activate with `source .venv/bin/activate`, or invoke tools directly via `.venv/bin/python`.
- `requirements.txt` mirrors the dependencies the generator itself installs into the scaffolded project (`typer[all]`, `beautifulsoup4`, `lxml`, `ijson`, `faster-whisper`, `orjson`, `jinja2`, `fastapi`, `uvicorn[standard]`). `sqlite3` is stdlib and intentionally omitted.

## Running

- `python3 setup_unified_timeline.py` runs the interactive generator. **Its `main()` is macOS-only**: `check_dependencies()` calls `sys.exit` on any non-Darwin platform, it prompts interactively via `input()`, and it shells out to Homebrew/`launchd`/`open`. It cannot run unmodified in a Linux environment.
- The individual scaffold-generation functions inside `setup_unified_timeline.py` (e.g. `create_directory_structure`, `create_config_file`, `create_pipeline_scripts`, `create_wrapper_script`) are ordinary importable functions and can be called directly for development/testing on Linux without going through the macOS-gated `main()`.
- Of the scripts the generator emits, the pipeline stages themselves have a platform split:
  - `01_fetch_messages.py` reads the local macOS Messages database (`~/Library/Messages/chat.db`) — macOS-only.
  - `02_transcribe_messages.py` runs `faster-whisper` over audio attachments — cross-platform, but depends on stage 1's output.
  - `06_merge_outputs.py` merges per-source JSONL files (`messages_enriched.jsonl`, `voice_events.jsonl`, `chat_events.jsonl`, `alexa_events.jsonl`) from a generated project's `data/outputs/` into `unified_jess_timeline.{json,md}` — this stage **does** run on Linux and has no macOS dependencies.
  - Stages `03`–`05` (Google Voice, Google Chat, Alexa parsing) are referenced by the wrapper script but not yet generated by `create_pipeline_scripts` — they're commented out in the emitted `run_timeline_update.sh`.

## No lint, type-check, or test tooling

There is no linter, type-checker, test runner, or build step configured in this repo. Don't assume `pytest`, `ruff`, `mypy`, etc. are available or wired up — check before invoking them, and don't add CI config or test scaffolding unless asked.

## Architecture of the generator script

`setup_unified_timeline.py` is a straight-line, single-file scaffolder — there's no package structure to navigate. Its functions run in sequence from `main()`, each responsible for one piece of the emitted project, and each writes files under a `base_path = Path("unified_jess_timeline")`:

1. `check_dependencies` — macOS/Python-version/Homebrew checks (gates everything else).
2. `install_python_packages` — pip-installs the pipeline's runtime deps directly (separate from this repo's own `requirements.txt`/`.venv`).
3. `create_directory_structure` — creates `scripts/`, `data/{cache,outputs}/`, `inputs/Takeout/{Voice,Google Chat}/`, `logs/`.
4. `create_config_file` — interactively prompts for Takeout path, Messages DB path, and the contact identifier to filter on, then writes `scripts/00_config.py` with those plus fixed paths/settings (batch size, Whisper model, output file paths).
5. `create_utility_scripts` — writes the generated project's own `requirements.txt` and `.gitignore`.
6. `create_pipeline_scripts` — writes the actual stage scripts (`01_fetch_messages.py`, `02_transcribe_messages.py`, `06_merge_outputs.py`) as string literals embedded in this generator. **To change pipeline behavior, edit the string literal here, not a file on disk** — there is no separate template file.
7. `create_wrapper_script` — writes `scripts/run_timeline_update.sh`, which runs the stages in order.
8. `create_launchd_plist` — writes a `launchd` plist for scheduling automatic re-runs on macOS (15-minute interval).
9. `create_readme` / `create_git_keep_files` — documentation and placeholder files for the emitted project.

Each generated pipeline stage script loads shared config by dynamically importing `00_config.py` via `importlib.util` (not a regular package import), since the scripts are numbered standalone files rather than a Python package.

Data flows between stages as JSONL files in `data/outputs/`: `messages_raw.jsonl` → (transcription) → `messages_enriched.jsonl`, alongside independently-produced `voice_events.jsonl`, `chat_events.jsonl`, `alexa_events.jsonl`. `06_merge_outputs.py` loads all of these, sorts by `timestamp`, and writes the unified `unified_jess_timeline.json` (with stats) and `.md` (grouped by date).
